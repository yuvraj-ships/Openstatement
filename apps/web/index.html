    How it reads
    a statement

    There's no code written for any particular bank. The same five steps handle a one-page credit-union PDF and a 40-page business statement.

    1. Reads the page, not just the words

      pdf.js pulls out every piece of text with its position, right here in your browser.

    2. Finds the ledger

      Rows that start with a date and carry an amount are transactions. Headers, footers and page numbers are left behind.

    3. Works out the local format

      A “25/02” can only be day-first. A “1.234,56” is a European thousand. Column headers are read in seven languages.

    4. Checks the arithmetic

      Every row's running balance must equal the last one plus the amount. If the columns are swapped, the balance gives it away — and it gets fixed.

    5. Learns your bank, once

      If something's off, fix the columns and share the layout as a tiny template. The next person with your bank gets it right automatically.

    Also a library.

    Use the same parser in your own app, script or backend. Zero runtime dependencies, typed, works in browsers and Node.

    $ npm install openstatement pdfjs-dist

import { parsePdf, toCSV } from 'openstatement';

const { transactions, meta } = await parsePdf(bytes, { pdfjs });
meta.confidence   // 1 → every running balance adds up
toCSV(transactions);
